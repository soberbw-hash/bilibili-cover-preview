## 这个工具是什么？

一张封面单独看起来不错，不代表放进推荐流后仍有点击欲。真正影响第一眼判断的往往是相邻封面的颜色、信息密度、人物比例、标题长度、界面明暗和卡片尺寸。

B站封面预览提供一个可重复的本地测试环境：导入自己的封面，把它放在 52 张示例封面之间，反复随机周围素材，并在网页端、手机双列流和深色模式中比较。它不预测真实点击率，但能帮助创作者更早发现“单看好看、放进信息流就消失”的问题。

## 为什么做它？

创作者常见的评审方式是把大图发到群里问“这张怎么样”。但观众真正看到封面时，它通常只有几百甚至一百多像素宽，旁边同时存在十几张完全不同的内容。

脱离信息流评审，会忽略几个关键问题：

- 大图上精致的细节缩小后全部消失；
- 文字在设计软件里清楚，放进手机双列卡片后无法阅读；
- 自己封面的色调与同屏内容太接近，失去视觉优先级；
- 浅色界面很醒目，深色界面却边缘混在背景中；
- 设计者永远知道“我的封面在哪”，无法模拟陌生观众的第一眼。

所以这个工具不替你设计封面，而是提供一个更接近发布现场的“试衣镜”。

## 核心设计原则

### 👀 在竞争环境里看，不单独看

自己的封面始终和一组真实风格的内容卡片一起出现；随机环境用于验证醒目程度是否稳定。

### 📱 小尺寸优先

网页大卡、普通推荐卡和手机双列流都要看。能在大图阅读不等于能在手机上阅读。

### 🔒 图片只留在当前页面

导入使用浏览器本地文件 API，没有上传接口、账号和云项目。刷新即清空是隐私边界，也是产品取舍。

### 🪶 打开就用

纯静态 HTML/CSS/JavaScript，不要求安装 Node.js、数据库或前端构建链。任何能启动静态服务器的设备都能使用。

### 🎯 不伪装成点击率预测器

工具只展示视觉上下文，不接入平台流量数据、用户画像或推荐算法。它能帮助发现问题，不能承诺流量结果。

### 🖥️ 1. 网页端首页环境

包含近似的顶部区、频道区、轮播大图、侧栏卡片和推荐网格，帮助检查封面在不同尺寸和位置中的表现。

### 📱 2. 手机端双列推荐流

把同一张封面缩到更苛刻的移动端卡片尺寸，重点暴露小字、弱主体和拥挤构图。

### 🖼️ 3. 52 张示例封面池

示例覆盖人物、摄影、足球、科技、教程、旅行和剧情等不同视觉风格。它们的作用是构造复杂背景，不是作为可自由再分发的素材包。

### 📥 4. 点击、双击与拖拽导入

可以从工具栏选择图片，也可以双击目标卡位或把文件拖到指定位置，方便测试首屏、普通卡和手机卡的不同曝光位。

### 🎲 5. 随机竞争环境

随机按钮只打乱周围示例封面，保留用户封面和选中位置。连续多次随机能减少“刚好旁边都是同色封面”的偶然结论。

### ✍️ 6. 自定义视频标题

标题与封面一起决定卡片信息量。输入真实标题后，可以检查标题长度、封面文字和主题承诺是否互相补充。

### 🌙 7. 深色模式

检查黑边、暗背景、白字和高光在深色内容流中的表现。按钮可随时切回浅色，不影响导入状态。

### 🏷️ 8. 我的封面标记

编辑时用高亮快速定位自己的卡片；正式判断时关闭标记，让眼睛像普通观众一样重新扫描页面。

### 🎞️ 9. 轮播大图

网页端大图支持自动轮播、圆点和前后切换，用于观察封面在大曝光位和动画切换中的视觉稳定性。

### 📸 10. 一键截图

截图前等待可见图片加载，并进入截图安全样式。支持剪贴板时直接复制；不支持或被拒绝时自动下载 PNG。

## 📥 快速开始

### macOS：双击启动

双击仓库中的：

```text
打开预览.command
```

脚本会在当前目录启动本地静态服务器，并打开：

```text
http://127.0.0.1:8765/index.html
```

### Windows / macOS / Linux：手动启动

只要本机有 Python 3：

```bash
python3 -m http.server 8765
```

Windows 也可以使用：

```powershell
py -m http.server 8765
```

随后访问：

```text
http://127.0.0.1:8765/index.html
```

项目不需要 npm、Node.js、数据库或构建步骤。

> [!IMPORTANT]
> 不建议用 `file://` 直接打开后截图。浏览器会对本地图片和 Canvas 导出施加安全限制，可能导致截图失败。通过 `127.0.0.1` 的本地静态服务访问即可。

## 🚀 3 分钟完成一次封面测试

1. 准备最终导出的 16:9 封面；
2. 点击“导入我的封面”，或把文件拖到想测试的卡位；
3. 输入准备使用的视频标题；
4. 连续点击多次“随机封面”，观察不同颜色和内容环境；
5. 切换网页端与手机端，先看 1 秒内能否读出主体和主题；
6. 切换深色模式，检查暗部是否糊成一片、亮部是否刺眼；
7. 打开“我的封面标记”确认位置，再关闭标记进行无提示比较；
8. 使用一键截图发给朋友或团队盲测。

### 第 1 分钟：缩小看主体

先不要开“我的封面标记”。在网页普通卡和手机双列流中，用一秒判断是否能看到主体、动作和主题。

### 第 2 分钟：换环境

连续随机至少 5 次，并切换浅色/深色。记录在哪些环境中封面消失，是颜色、亮度、构图还是文字造成的。

### 第 3 分钟：截图盲测

隐藏标记，截取完整内容流，让没有参与设计的人在 3 秒内指出最想点的卡片和他们理解的内容。不要先告诉对方哪张是你的。

> [!TIP]
> 同一张封面准备 2–3 个版本，每次只改变一个变量，例如标题字号、主体大小或背景颜色。一次全改很难知道真正有效的是哪一步。

<a id="checklist"></a>

## 🧭 封面诊断清单

### 第一层：一秒辨识

- 主体是否一眼可见；
- 背景是否与主体分离；
- 小尺寸下文字是否仍能读懂；
- 是否需要依赖标题才能明白内容。

### 第二层：与周围封面的竞争

- 色相和亮度是否与相邻卡片过于接近；
- 人脸、物体或文字是否被卡片裁切；
- 信息密度是否明显高于同屏内容；
- 视觉中心是否稳定，还是有多个元素争抢注意力。

### 第三层：承诺是否准确

- 封面与标题是否表达同一个主题；
- 画面是否让人误判内容类型；
- 是否为了醒目而牺牲可信度；
- 截图发给不熟悉视频的人时，能否说出大致内容。

本工具只帮助观察视觉呈现，不会计算真实推荐权重、点击率或平台审核结果。

### 第四层：移动端生存

- 文字缩到手机卡片后是否还能读；
- 关键人物和物体有没有被裁掉；
- 主体是否依赖细小表情或手势；
- 画面中的边框是否在小尺寸变成噪声；
- 标题和封面是否重复写同一句话。

### 第五层：多环境稳定性

- 浅色和深色界面是否都能看清边缘；
- 相邻封面换成暖色、冷色或高亮时是否仍可辨识；
- 在轮播大图与普通小卡中是否都保持主题；
- 去掉“我的封面标记”后，自己能否重新快速找到；
- 陌生人对内容的理解是否与视频实际一致。

## 🧪 三种对比方法

### A/B 单变量对比

保持图片内容不变，只改一个元素，例如文字大小或背景明度。分别截图，让测试者不看文件名选择。

### 随机环境压力测试

同一版本连续随机多次，记录它在哪类相邻封面旁边失去注意力。这比只挑一张“效果最好”的截图更有参考价值。

### 无提示三秒测试

隐藏标记，把截图给第一次看到的人三秒，然后关闭图片，询问他记住了哪张、看懂了什么。记忆结果通常比“挺好看的”更有信息。

## 📸 导入与截图行为

- 导入图片通过浏览器 `FileReader` 在本地读取；
- 图片不会发送到服务器，本项目也没有上传接口；
- 刷新页面后，当前导入内容不会作为云端项目保存；
- 截图功能在需要时从仓库本地加载 `html2canvas`；
- 支持剪贴板写入的浏览器会直接复制 PNG；
- 浏览器拒绝剪贴板权限时，会自动改为下载文件；
- 截图前会等待可见封面完成加载，并临时进入截图安全样式。

若截图不完整，先等待封面加载完成，保持目标区域可见，再重试；仍失败时使用浏览器原生截图作为备选。

### 为什么截图要通过本地服务器？

浏览器会把 `file://` 页面加载的本地图片视为不同安全来源，Canvas 一旦被这些图片污染就不能导出。`http://127.0.0.1:8765` 让页面、脚本和图片来自同一来源，截图功能才能稳定工作。

### 图片会保存在哪里？

导入内容在当前页面内存中使用。工具没有项目文件、云端存储或后台上传；截图下载位置由浏览器设置决定。

## 🌐 浏览器兼容性

建议使用最新版 Chrome、Edge 或其它 Chromium 浏览器。Safari 和 Firefox 可以完成大部分预览，但剪贴板、Canvas 和本地文件权限策略不同，截图可能自动退化为文件下载。

移动浏览器可查看页面，但“手机端”按钮主要用于在桌面浏览器内模拟双列信息流尺寸，并不等于真实 App 渲染。

## 🔒 隐私与安全

- 没有账号、分析脚本、广告 SDK 或遥测；
- 没有后端和数据库；
- 用户导入图片只存在于当前页面内存；
- 自定义标题只用于当前页面预览；
- 项目不会读取图片之外的本地文件；
- 公开部署时，任何访问者都能下载随站点发布的示例素材，因此必须先确认素材授权。

> [!WARNING]
> “本地预览可用”不代表“公开部署可用”。示例封面可能受版权、肖像、商标或平台规则限制，发布公开站点前应替换为自有、获授权或明确可再分发的素材。

## 🗂️ 更新示例封面库

将新的 JPG/PNG 封面放进 `covers/`，再在 `index.html` 的 `competitorCovers` 数组中添加记录：

```js
{
  cover: 'covers/你的封面文件名.jpg',
  title: '参考视频标题',
  owner: '参考UP',
  viewText: '12.3万',
  danmakuText: '88',
  durationText: '08:30',
  sourceName: '其他博主封面'
}
```

维护素材时请：

- 使用相对路径，避免提交本机绝对路径；
- 检查文件名大小写，GitHub Pages 区分大小写；
- 压缩过大的图片，避免首次加载过慢；
- 记录素材来源和使用依据；
- 不提交包含私人信息、未公开人物或无权使用的商业素材。

## 🚀 部署

入口文件是 `index.html`，可部署到 GitHub Pages、Vercel、Netlify 或任意静态文件服务。

### GitHub Pages

1. 在仓库 Settings → Pages 中选择从分支部署；
2. 选择 `main` 分支和根目录；
3. 等待 Pages 构建完成；
4. 打开站点，测试封面加载、拖拽和截图。

仓库包含 `.nojekyll`，用于避免 GitHub Pages 走 Jekyll 处理流程。

### 部署前检查

- `index.html` 可打开；
- `covers/` 和 `assets/` 路径均为相对路径；
- 深色模式、网页/手机切换正常；
- 拖拽、文件选择和标题输入正常；
- 截图能复制或下载；
- 示例素材已获得公开分发权。

## 🛠️ 本地开发

项目采用单文件主应用结构，修改 `index.html` 后刷新浏览器即可验证。提交前至少手工检查：

- 1440px 以上桌面窗口；
- 接近最小支持宽度的窗口；
- 网页端和手机端；
- 浅色和深色模式；
- 未导入、已导入、重复替换和拖拽状态；
- 轮播自动切换与手动切换；
- 截图剪贴板成功和下载退化路径；
- 键盘焦点、按钮名称和赞助弹窗关闭行为。

### 性能注意事项

- 新封面尽量压缩，避免几十张高分辨率 JPG 同时占用内存；
- 保留懒加载和空闲时加载逻辑；
- 不把截图依赖改成外部 CDN，否则离线使用和隐私边界会变化；
- 新增动画时尊重浏览器性能与减少动态效果偏好；
- 变更卡片结构后同时验证桌面截图和手机截图裁切。

## ❓ 常见问题

### 为什么截图按钮提示失败？

先确认不是通过 `file://` 打开，并允许浏览器写入剪贴板。无法写剪贴板时工具会尝试下载 PNG；企业浏览器策略可能同时限制两者。

### 为什么导入图片后刷新就没了？

这是隐私设计的一部分：当前版本不把用户图片上传或持久化。需要保留结果时请导出截图。

### 可以直接拿来预测点击率吗？

不可以。工具只提供视觉对照环境，不接入 B 站后台数据，也不模拟推荐算法。

### 可以把示例封面一起部署到公开网站吗？

不应默认这样做。示例封面版权归对应权利方，公开部署或再分发前必须逐一确认权利或换成自有/已授权素材。

### 为什么不直接双击 `index.html`？

预览本身可能正常，但本地图片会触发 Canvas 跨来源限制，导致一键截图失败。使用启动脚本或本地静态服务器最稳妥。

### 支持 PNG、WebP 或 GIF 吗？

文件选择接受浏览器可解码的图片格式。动图是否保留动画、截图如何取帧取决于浏览器；封面评审建议使用最终静态导出图。

### 会自动裁成 B 站比例吗？

卡片会按界面尺寸展示，但工具不替你重新设计安全区。最好先导出最终比例，再检查关键内容是否被裁切。

### 为什么“随机封面”没有移动我的封面？

这是有意设计：随机只改变竞争环境，保持测试对象和位置不变，便于比较。

### 手机端预览等于真实 App 吗？

不等于。它是近似的双列信息流环境，用于尺寸和对比测试，不保证像素级复刻官方 App。

### 能保存多个方案吗？

当前不提供项目存储。可以分别截图或给文件命名；保持无后端是工具轻量和隐私设计的一部分。

### 能不能自动给封面打分？

当前不会。脱离内容、受众和真实数据的单一分数很容易制造假精确，项目优先提供可观察的对比环境。

### 为什么没有真实播放量和 UP 主数据？

示例字段只为了构成视觉卡片，不接入 B 站 API，也不应被当作真实数据分析工具。

### 可以修改代码做自己的平台预览器吗？

项目代码采用 MIT，可以修改和再分发，但必须保留版权与许可；示例图片和平台商标不自动随代码授权。
